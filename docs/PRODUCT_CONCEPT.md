# Prompt Defense — 当前产品概念

> 状态：截至 2026-09-21 已确认的产品方向。
> 本文档只记录已经做出的决定。未决事项在文末单独列出。

## 1. 产品概念

**Prompt Defense** 是一款基于网页的无限 roguelike 塔防游戏，其中人类不直接控制战场。

人类编写并更新自然语言的策略 Prompt。一个 AI 玩家观察游戏状态，并按照这些指令操作塔防游戏。

核心关系是：

**人类意图 → Prompt → AI 决策 → 游戏行动 → 战场结果**

核心玩家幻想是：**“我教 AI 怎么玩，然后看我的策略能不能活下来。”**

这款游戏应该让黑客松现场的人可以直接在网页浏览器中游玩，包括现场参与者，而不是仅仅作为一个给评委看的 demo。

## 2. 目标体验

长期目标受众是正在学习如何与 AI 互动的青少年 / 年轻人。

游戏首先应该以游戏的身份吸引他们。学习成果来自反复地给 AI 下指令、观察它实际做了什么，并修订策略。

产品不应主要让人感觉像一门 Prompt Engineering 课程。

底层的学习循环是：

**意图 → 指令 → 行为 → 观察 → 修订**

通过游玩，玩家可以学到目标、上下文、约束、优先级、例外、反馈、通用策略与硬编码指令有何不同，以及当指令改变时 AI 行为会如何变化。

诸如 CO-STAR 这类结构化 Prompt 方法可以通过学习体验引入，但目前尚未选定任何单一的 Prompt 框架作为游戏的官方框架。

## 3. 核心游戏循环

当玩家花费一枚硬币（Coin）时，一局正式游戏开始。

**1 Coin = 1 局 / 一条命**

在该局中：

1. 玩家给 AI 一个初始策略 Prompt。
2. AI 自主游玩塔防游戏。
3. 波次持续进行，并越来越难。
4. 玩家观察战场与 AI 的行为。
5. 在该局仍在进行时，玩家可以通过编写新的 Prompt 来更新策略。
6. 更新后的策略影响后续的 AI 决策。
7. 这个过程持续到基地被摧毁。
8. 玩家的得分是该局中到达的最高波次。

因此，Prompt 在**一局开始时并不被锁定**。一局可以包含 Prompt v1 → Prompt v2 → Prompt v3 → …… → 基地被摧毁。

这让游戏变成持续的人机协作，而不是在开玩前写下一条完美指令。

## 4. 无限 roguelike 塔防

塔防基础必须支持**无限波次（endless Waves）**。没有固定的最终关卡。难度持续上升，直到玩家的防御失败。

游戏还包含 roguelike 随机性。同一个策略**不一定**在每一局都产生相同结果。

**Prompt 决定策略 / 方针。RNG 决定策略所遇到的情境。**

因此，一个好的 Prompt 应该表达可复用的决策规则，而不是记住固定的波次序列。

示例：

- 脆弱的指令：“在第 5 波升级加农炮。”
- 通用策略：“当出现高 HP 敌人时，优先选择高单体伤害。”

roguelike 环境让这种差别变得可观察。

## 5. 人类与 AI 的角色

### 人类

人类是 AI 的战略家 / 训练师。人类编写策略 Prompt，观看 AI 游玩，观察失败和不断变化的战场条件，在一局进行中更新 Prompt，并决定如何传达目标、约束、优先级和例外。

在正常游玩中，人类**不**直接操作防御塔。

### AI

AI 是战场上的玩家。它接收玩家当前的策略 Prompt，观察当前游戏状态，决定要采取哪些塔防行动，只执行游戏所暴露的动作，并随着游戏演进而持续行动。

逐帧模拟（例如敌人移动、防御塔攻击、伤害与动画）由常规游戏引擎处理，而非 LLM。

## 6. 教程 / 首次体验

首次游玩的玩家在需要自己写 Prompt 之前，必须先看到一个示例 Prompt。

教程应该演示一个 Prompt 可以包含不同种类的指令，例如目标、策略、资源约束、优先级和特殊规则。

教程的关键成果是：

**玩家改变一条指令，然后看到 AI 在游戏中表现出不同行为。**

这建立起因果模型：

**我的话改变了 AI 的行为。**

在玩家理解基本交互之后，游戏可以逐步引入更复杂的 Prompt 结构和策略。

具体的教程场景与推进方式尚未确定。

## 7. 局内策略更新

策略更新是游戏已确认的一部分。

玩家必须能够观察一局进行中的游戏，并判断 AI 需要新的指令。系统应保留一局的策略演化过程，而不是只存储其最终 Prompt。

概念上：

本局
- Prompt v1 — 从第 … 波起生效
- Prompt v2 — 从第 … 波起生效
- Prompt v3 — 从第 … 波起生效
- 最终结果

这段历史之后可以支持局后学习，以及对排行榜上强势局的分析。

在一局中更改 Prompt 的具体成本、冷却、时机或限制尚未确定。

## 8. 硬币（Coin）

游戏使用 **投入 1 枚硬币（INSERT 1 COIN）** 这一隐喻。

一枚硬币代表无限塔防中的一次尝试 / 一条命。花费一枚硬币开始一局正式游戏。如果基地被摧毁，该局结束。开始另一局需要另一枚硬币。

对本次黑客松而言，Coin 是一种游戏机制，**并不意味着真实货币支付**。

初始硬币配额与补充机制尚未确定。

## 9. 得分与排行榜

主要得分是**到达的波次（Wave Reached）**。

网页游戏有一个共享排行榜，方便黑客松参与者比较各自的成绩。

排行榜基于每局表现，同时承认 roguelike 随机性意味着单次最佳成绩并不是对 Prompt 质量的科学测量。

玩家应该能够查看其他玩家成功的策略 / Prompt 历史，让竞争同时带来同伴学习。

由此形成的社交循环是：

**游玩 → 排名 → 查看 → 学习 → 改变策略 → 再试一次**

确切的排名公式、平局规则以及公开的 Prompt 信息量尚未确定。

> **当前实现（2026-09，过渡阶段）**：线上尚无后端，且 AGENTS.md 禁止上线可通过客户端伪造成绩的排行榜接口。因此当前先交付**纯前端本地排行榜**：首次进入时提示输入用户名（写入 cookie），排行榜按「到达的最高波次」排序；游戏开始及每次到达新波次时更新本地最佳成绩与个人排名，界面左下角显示前十与当前用户的排名，登上前十高亮；数据存于本地（localStorage / cookie）。跨设备与跨用户的真实共享排行榜仍需先完成后端技术选型与服务端对局校验设计（见文末「身份与后端」「排行榜」未决问题），届时用服务端实现替换本地实现。

## 10. 网页 / 现场体验

产品是一款**网页游戏**。

黑客松版本应允许现场的人直接用自己的浏览器参与，而不需要安装。

期望的现场循环是：

打开游戏 → 理解“我教 AI” → 游玩 / 花费一枚 Coin → AI 作战 → 需要时更新策略 → 本局结束 → 出现得分 → 排行榜 → 查看其他策略 → 再试一次。

共享的实时排行榜是产品概念的一部分。

## 11. 核心产品神奇时刻

本项目的核心证明是：

**玩家改变 Prompt，AI 改变行为，战场作为结果发生可见变化。**

这应该在不同局之间，以及同一局内策略更新之后，都可以被观察到。

如果 Prompt 的改变不能产生清晰可辨的行为差异，核心产品就不成立。

## 12. 产品定位

当前简洁表述：

**Prompt 是你的策略。AI 是你的玩家。塔防是这个世界。**

面向玩家的表述：

**教你的 AI。把它送上战场。看它能活多久。**

更深层的教育命题是：玩家通过观察指令如何变成行动，并基于真实结果修订它们，学会如何向一个自主 AI 传达意图。

## 13. 当前 MVP 边界

MVP 必须建立：

- 一款网页版塔防游戏；
- 无限波次；
- roguelike / 随机化遭遇；
- 一个能自主操作游戏的 AI；
- 玩家可编辑的策略 Prompt；
- 一局进行中的 Prompt 更新；
- 可见的 AI 行动与战场结果；
- 每局正式游戏消耗一枚 Coin；
- 以“到达的波次”为主要得分；
- 面向参与者的共享排行榜；
- 包含示例 Prompt 的首次教程；
- 能够学习其他玩家成功策略的能力。

第一个工程里程碑是把选定的开源网页塔防基础改造为可被 AI 操作的无限模式，见第 14 节与 issue #7。

## 14. 技术底座与部署

### 塔防底座

采用 [CorentinTh/inert](https://github.com/CorentinTh/inert)（MIT，TypeScript，约 2200 LOC）。

选择理由：原生支持无限波次与 RNG 波次生成；已有 5 种敌人与 5 种防御塔，策略空间足以让不同 Prompt 分化；A* 寻路 + 「塔即墙」使放置位置本身具有战略含义。落地事项见 issue #7 及其子项。

需要自行补齐的能力：防御塔升级 / 出售（inert 原版没有）。

### LLM 供应商

采用 **DeepSeek**。

这不是一次自由选择，而是由部署环境的网络约束决定的。在目标服务器上实测（2026-09-21）：

| 端点 | 结果 |
|---|---|
| `api.anthropic.com` | HTTP 403 `Request not allowed` —— Cloudflare 地域封锁 |
| `api.openai.com` | 完全不通，DNS 被污染至哨兵地址 |
| `api.deepseek.com` | HTTP 401 `Authentication Fails` —— 仅缺密钥，链路正常 |

DeepSeek 走国内 CDN 线路，实测 TLS 握手 25–80ms、请求总计约 100–160ms。由于 `docs/IDEA.md` 把决策延迟设计成了游戏机制（「Think fast or die」），低延迟链路对玩法本身有价值，而不只是运维收益。

同一约束也意味着：**玩家浏览器在国内网络下同样无法直连 Anthropic / OpenAI**，因此 LLM 调用必须经由服务端代理。这与密钥不得进入前端的要求方向一致。

### 部署环境约束

部署目标已确定，是一台位于中国大陆、已承载其他生产业务的小规格共享服务器。具体主机、凭据与运维细节由运维负责，不在本仓库记录。

对开发有约束力的是以下三条，与具体主机无关：

- **构建不在服务器上执行。** 目标机内存余量有限，构建峰值会挤压既有生产服务。前端构建在本地或 CI 完成，仅上传产物。
- **新服务必须与既有生产业务隔离**：独立系统用户、独立数据库、进程内存上限、反向代理限流。
- **LLM 调用必须经服务端代理**，原因见上一节。

资源规格本身不是瓶颈：游戏的 LLM 调用是 I/O 等待而非 CPU 密集，真正的上限来自模型供应商的速率限制与成本，而不是这台机器。

### 前端部署流水线

静态前端的持续部署已建立（2026-09-22 确认）。

- **触发与构建**：push 到 `main` 由 GitHub Actions 构建，PR 只构建不部署。构建在 CI 完成，
  仅把产物上传到服务器，符合上一节「构建不在服务器上执行」。
- **版本布局**：产物按 commit sha 落在 `releases/<sha>/`，`current` 符号链接原子切换指向生效版本，
  保留最近 5 个版本。回滚是改一次符号链接，不需要重跑 CI。
- **隔离**：独立系统用户，无 sudo，可写范围仅限本应用目录；nginx 配置只新增，不修改既有站点。
- **证书**：复用目标机上已有的 `*.crowntime.cn` 通配符证书，不单独签发。
  代价是与提供该证书的应用存在续期耦合，已知并接受。

具体主机、域名以外的凭据与路径仍不在本仓库记录，落在 GitHub Secrets 与服务器本地。
开发者须知见 `docs/DEPLOYMENT.md`（代码怎么上线、写代码时的约束）；
服务器初始化与回滚等运维操作见 `deploy/README.md`。

本流水线与打包器无关（入口始终是 `npm run build` → `dist/`），issue #1 迁移到 Vite 后无需改动。

**本次部署不含任何 LLM 能力**，上线的是塔防底座本身；服务端代理待后端技术栈选型后另行处理。

# 未决问题 / 遗留决策

以下事项**尚未**决定，目前不得视为需求。

### 塔防基础

- 确切的地图设计。
- 固定路线还是其他路径模型。
- 确切的防御塔类型与敌人类型。
- 防御塔放置模型。
- 难度缩放公式。
- RNG / 种子设计。

### Agent 运行时

- 确切的 GameState schema。
- 确切的 action / tool schema。
- 允许 AI 多久做一次决策。
- 决策是按波次、事件驱动，还是按其他节奏。
- 模型延迟应如何影响游戏体验。

### Prompt 系统

- 确切的 Prompt 长度 / 预算。
- Prompt 更新是否有冷却、有限次数、资源成本或波次限制。
- 游戏是否采用自定义的 Prompt 框架。
- 如何教授 CO-STAR 或其他 Prompt 框架。
- 确切的策略历史 UI。
- 玩家是否可以分叉 / 复制其他玩家的 Prompt。

### 教程

- 确切的教程波次。
- 教程是否故意让 AI 死亡，还是允许玩家在失败前介入。
- 确切的示例 Prompt。
- 确切的教学推进方式。

### 硬币经济

- 初始硬币数量。
- 硬币补充。
- Coin 是否会成为某种变现机制。

### 排行榜

- 排名是纯粹的最佳波次，还是包含其他模式。
- 平局规则。
- 随机性如何呈现。
- 是否展示平均 / 中位数表现。
- 玩家的 Prompt / Prompt 历史有多少是公开的。
- 回放要求。
- 反作弊 / 对局校验设计。

### 身份与后端

- 仅昵称还是账号。
- 持久化机制。
- 数据库选择。
- 后端技术栈。
- 移动端 / 桌面端 UI 细节。

### 未来范围 — 目前不属于 MVP

以下想法已经讨论过，但不是当前 MVP 的承诺：

- 多 Agent / Swarm；
- 单人 vs Swarm；
- Prompt 卡牌；
- Prompt 继承 / 记忆；
- Prompt 演化；
- Prompt vs Prompt 对抗；
- 自带 Agent；
- 多模型竞赛；
- 进阶 Agent 基准测试。
