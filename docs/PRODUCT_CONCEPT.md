# Prompt Defense — 当前产品概念

> 状态：截至 2026-09-22 已确认的产品方向。
> 本文档只记录已经做出的决定。未决事项在文末单独列出。

## 1. 产品概念

**Prompt Defense** 是一款基于网页的无限 roguelike 塔防游戏，其中人类不直接控制战场。

> **命名（2026-09-22 确认）：** 游戏对玩家的展示名为**「保护笑脸男」**，出现在页面标题、品牌标题、页脚与 PWA 应用名中。**「Prompt Defense」**保留为本项目与仓库的代号，不在游戏界面展示。

人类编写并更新自然语言的策略 Prompt。一个 AI 玩家观察游戏状态，并按照这些指令操作塔防游戏。

核心关系是：

**人类意图 → Prompt → AI 决策 → 游戏行动 → 战场结果**

核心玩家幻想是：**“我教 AI 怎么玩，然后看我的策略能不能活下来。”**

这款游戏应该让黑客松现场的人可以直接在网页浏览器中游玩，包括现场参与者，而不是仅仅作为一个给评委看的 demo。

## 2. 目标体验

长期目标受众是正在学习如何与 AI 互动的青少年 / 年轻人。

游戏首先应该以游戏的身份吸引他们。学习成果来自反复地给 AI 下指令、观察它实际做了什么，并修订策略。

产品不应主要让人感觉像一门 Prompt Engineering 课程。

底层的学习循环是：

**意图 → 指令 → 行为 → 观察 → 修订**

通过游玩，玩家可以学到目标、上下文、约束、优先级、例外、反馈、通用策略与硬编码指令有何不同，以及当指令改变时 AI 行为会如何变化。

诸如 CO-STAR 这类结构化 Prompt 方法可以通过学习体验引入，但目前尚未选定任何单一的 Prompt 框架作为游戏的官方框架。

## 3. 核心游戏循环

玩家输入昵称后进入游戏，选择或编写初始策略 Prompt，一局游戏随即开始。

> **Hackathon MVP 不引入 Coin 经济。** 编辑 Prompt 与重开一局都不消耗资源。Coin 是否在未来版本回归尚未决定。

在该局中：

1. 玩家给 AI 一个初始策略 Prompt。
2. AI 自主游玩塔防游戏。
3. 波次持续进行，并越来越难。
4. 玩家观察战场与 AI 的行为。
5. 在该局仍在进行时，玩家可以随时修改策略 Prompt（不必先暂停）。新 Prompt 在当前波结束时、AI 下一次思考（`PLANNING`）时生效。
6. 更新后的策略影响后续的 AI 决策。玩家也可以 PAUSE 冻结战场观察，恢复需要手动 RESUME。
7. 这个过程持续到基地被摧毁。
8. 玩家的得分是该局中到达的最高波次。

因此，Prompt 在**一局开始时并不被锁定**。一局可以包含 Prompt v1 → Prompt v2 → Prompt v3 → …… → 基地被摧毁。

这让游戏变成持续的人机协作，而不是在开玩前写下一条完美指令。

## 4. 无限 roguelike 塔防

塔防基础必须支持**无限波次（endless Waves）**。没有固定的最终关卡。难度持续上升，直到玩家的防御失败。

游戏还包含 roguelike 随机性。同一个策略**不一定**在每一局都产生相同结果。

**Prompt 决定策略 / 方针。RNG 决定策略所遇到的情境。**

因此，一个好的 Prompt 应该表达可复用的决策规则，而不是记住固定的波次序列。

**敌方数值与波次组成（2026-09-23 / 24 确认）：**第 1–200 波中，敌人的生命值和速度在原有有效数值上提升 30%，即将原有 0.4 系数调整为 0.52。第 201 波起只生成 Boss；Boss 属性与数量保持此前第 152 波的原始值，不受 30% 提升影响：生命 12,960（2,000 × 16.2 × 0.4）、速度 1.0（2.5 × 0.4）、奖励 100、半径 16；每个启用出生点生成 16 只 Boss。后续波次不再增加 Boss 属性或数量。

示例：

- 脆弱的指令：“在第 5 波升级加农炮。”
- 通用策略：“当出现高 HP 敌人时，优先选择高单体伤害。”

roguelike 环境让这种差别变得可观察。

### Wave 256 彩蛋（已确认的后续方向，非当前 MVP 交付）

玩家**完成第 256 波后**进入「THE ENDLESS」彩蛋页，展示黑客松相关照片与制作组照片。战场停在彩蛋页，不自动进入下一波；只有玩家点击「继续无尽挑战」后，才在**同一局**继续第 257 波及后续无限波次。彩蛋不是 Game Over，也不封顶最终波次。

照片的具体选用与公开授权仍待确认；未获得出镜者同意或素材使用许可前不发布照片。此处只记录已确认的体验方向，不代表 #6 的 Prompt 行为验证已通过，也不将彩蛋纳入当前 MVP 实现范围。

## 5. 人类与 AI 的角色

### 人类

人类是 AI 的战略家 / 训练师。人类编写策略 Prompt，观看 AI 游玩，观察失败和不断变化的战场条件，在一局进行中更新 Prompt，并决定如何传达目标、约束、优先级和例外。

默认（**AI 模式**）下人类**不**直接操作防御塔：炮台只能由 AI 按 Prompt 指定的策略安排。**没有 Prompt 就不能开始一局**——`IDLE` 下 Start 按钮在策略为空时不可用。

为对照与演示，另有一个**人类模式**（页面上的「Switch to human play」按钮，或链接参数 `?mode=human`）：提供基于上游 inert 的直接操作玩法，显示炮台面板，支持鼠标手动放塔及选中已建炮塔后查看等级、费用与实时战斗属性并手动升级；升级由引擎校验资源与等级边界，成功后即时作用于战斗。AI 完全不参与，并在波间显示 7 秒倒计时（原版 `delayBetweenWaves`）。人类模式同样需在开局前确认昵称（`UsernameGate`），确认后自动开始对局，且成绩记录在专属的人类排行榜（见 §9）。切换模式会重启游戏，避免一局被两侧同时控制。

### 波次路线推进（2026-09-23 确认）

路线数按波次自动推进，取代手动选择与旧 `spawners` 参数：
- 第 1–50 波：1 条出生路线；
- 第 51–100 波：2 条出生路线；
- 第 101–150 波：3 条出生路线；
- 第 151 波起：4 条出生路线。

波次边界严格遵循「更新路线数 → AI 观察并规划 → 开始出兵」的时序。地图底座与建造校验从第 1 波起保证所有四个未来出生点至基地的通路不被炮塔或地形永久封死。

### 天然机油道具（2026-09-23 确认）

- 售价 2000 金币；人类界面只能在 `RUNNING` 时点击使用。AI 在 `PLANNING` 调用 `use_item` 会排队，并在本波首批敌人出现后尝试执行，仍按运行状态校验。
- 效果：所有己方正攻击间隔炮塔攻速提升 50%（攻击间隔按 1 / 1.5 缩短），持续 5 秒，结束后进入 10 秒冷却；不叠加。
- 持续与冷却按游戏模拟时间计算：暂停与 `PLANNING` 冻结计时，游戏加速等比缩短现实耗时。

### 黑客松主题战术道具（核心已实现；2026-09-23 确认补齐前端展示）

四件道具采用「名称来源｜九课装备代号」的展示命名方向，将黑客松要素融入战术终端，而不是只在鸣谢中出现。**EvoMap 是本届黑客松的发起人及主要赞助商**，在道具清单与未来赞助商鸣谢中列于首位；鸣谢页面的具体位置与形式仍待决定。

| 展示名 | 效果方向 | 当前状态 |
|---|---|---|
| **EvoMap｜全域轨道打击** | 对全图敌人造成一次范围伤害 | 已实现并接入 UI |
| **Tripo｜火力重构** | 短时强化己方炮塔火力 | 已实现并接入 UI |
| **Seeed Studio｜天然机油** | 短时提高己方炮塔攻速 | 已实现为独立道具并接入 UI（与原有天然机油按钮并存） |
| **HyperShell｜外骨骼应急修复** | 回复主基地生命 | 已实现并接入 UI |

四件道具的实际效果只在 `RUNNING` 状态执行：Tripo 单发伤害 ×3、Seeed Studio 攻速 ×1.5（均持续 5 秒），EvoMap 对存活敌人造成**当前**生命值 2% 的伤害（至少 1 点），HyperShell 回复基地最大生命值的 25%；使用后均冷却 10 秒。AI 在每波 `PLANNING` 中调用 `use_item` 时，引擎接受并排队该请求，在本波首批敌人生成后、仍处于 `RUNNING` 时重新校验资金与冷却并执行；执行结果另记入行动日志。人类界面仍只允许在 `RUNNING` 时直接使用。EvoMap 前两次免费，之后每次 1000 战术资源；其他三件每次 1000。这里记录的是**已上线的实现现状**，不是对最终平衡数值或后期权限设定的确认。EvoMap 的轨道打击与 Wave 151 后「九课中央网络离线、指挥权限被撤销」的剧情仍有待解冲突；不编造其可用性设定。品牌名的公开使用还需核实名称与素材许可，不因列在道具名称中就宣称官方合作或背书。

用户确认四件已上线并要求补齐界面入口，本次仅展示和调用现有核心，**不进一步扩大 #6 前的系统范围**。

### AI

AI 是战场上的玩家。它接收玩家当前的策略 Prompt，观察当前游戏状态，决定要采取哪些塔防行动，只执行游戏所暴露的动作，并随着游戏演进而持续行动。

观察必须覆盖地图上**所有**出兵路线（路数可在一局中变化）：状态里给出每条路线与各自的候选建塔格，且每个候选格标明它防守哪一路。系统指令要求 AI 覆盖每一路，除非玩家策略另有要求——否则 AI 会只堆在第一条路上。

状态还区分两类候选格：`buildCandidates` 是路线**旁边**、以火力覆盖敌人流量的格子；`pathShapingCandidates` 是路线**之上**、建塔后会让敌人绕远路的格子，各自附带增加的格数（`addedTiles`）。后者让「绕圈 / 蛇形 / 迷宫 / 拉长路径」这类策略有可执行的落点——引擎保证这些格子不封死任何一路，并在建塔后自动重算寻路。系统指令明确：玩家策略优先于默认的「覆盖每一路」（2026-09-22）。

**方位、网格坐标与工具调用顺序（2026-09-24 确认）**：系统提示词将地图左上角作为 `(0,0)`，坐标从 0 开始，`i` 为列并向右递增，`j` 为行并向下递增。四个固定敌方出生点分别为 `(4,26)` 西南、`(56,4)` 东北、`(56,26)` 东南、`(4,4)` 西北。每波启用的出生点数量会变化；AI 必须以当前状态的 `spawns` 为准，再按人类描述的方位和参考点坐标选择附近格子，不得假设四个点都启用。每个动作都使用独立工具调用，多个调用按依赖与优先级排列，由运行时按返回顺序逐个执行；每次决策最多返回 8 个调用，更多动作延后到后续波次。

逐帧模拟（例如敌人移动、防御塔攻击、伤害与动画）由常规游戏引擎处理，而非 LLM。

**决策可读性（2026-09-23 修订）**：左侧「塔奇克马判断」展示简短的玩家可见宏观战局研判（敌情威胁、路线覆盖意图、战术取舍），字数受限（<=120字），严禁包含具体坐标数字或机械动作复述。下方执行日志单独展示引擎实际接受或拒绝的具体动作与落点坐标。彻底废除原“没有公开说明时展示动作简短计划”的兜底逻辑；无公开宏观研判时展示本地化占位符（如“本轮暂无战术研判”），绝不以动作坐标冒充战略意图。研判语言与玩家界面语言（zh/en）严格绑定，界面切换时即时清空旧语言历史缓存。继续绝对禁止展示 `reasoning_content` 等原始思维链。展示内容只用于观察决策，不参与动作合法性判定或逐帧模拟。

## 6. 教程 / 首次体验

首次游玩的玩家在需要自己写 Prompt 之前，必须先看到一个可用的示例。MVP 用 **示例策略** 承担这一角色：目前实现为策略面板上的 **Random strategy** 按钮，点击后随机把一条示例填入 YOUR STRATEGY，玩家可以直接采用、在其基础上修改，或自己写。完整的多选项 Quick Start 列表（一次展示「基地防御」「沿途拦截」等多个选项）仍属后续范围。

示例不是纯文字模板：不同示例必须导致 AI 出现可观察的不同行为，例如「围绕基地建塔」与「沿敌人路线布防」应产生明显不同的部署方式。

首次体验的关键成果是：

**玩家改变一条指令，然后看到 AI 在游戏中表现出不同行为。**

这建立起因果模型：

**我的话改变了 AI 的行为。**

带脚本、故意让 AI 失败的完整教程属于 MVP 之外，具体场景与推进方式尚未确定。

## 7. 局内策略更新

策略更新是游戏已确认的一部分。

玩家必须能够观察一局进行中的游戏，并判断 AI 需要新的指令。系统应保留一局的策略演化过程，而不是只存储其最终 Prompt。

概念上：

本局
- Prompt v1 — 从第 … 波起生效
- Prompt v2 — 从第 … 波起生效
- Prompt v3 — 从第 … 波起生效
- 最终结果

这段历史已经作为本次 MVP 的局后学习闭环实现：服务端保存每局真正生效的版本链，排行榜用户可以打开其最高波次对局查看。未进入 `PLANNING` 并生效的草稿或被覆盖的排队版本不进入公开历史。

生效时机已确认（2026-09-22，见 issue #17；`IDLE` 与「第 1 波前先思考」于同日补充）。玩家随时可以编辑 Prompt，**不要求先暂停**：

- **一局从 `IDLE` 开始。** 打开页面后模拟与出怪都冻结，玩家先写开场 Prompt，再显式开始。
- **一个 wave 对应一个 Prompt 版本。** 进入该波 `PLANNING` 的瞬间锁定；该波行为不受中途修改影响。
- **开局 Prompt 在点击 Start 的瞬间先锁定**（不等第 1 波 `PLANNING`），因此第 1 波 `PLANNING` 的锁定是幂等的；即使那次通知被错过，第 1 波也绝不会用上一版/空白策略开局。
- 新 Prompt 在**下一个 `PLANNING`** 生效。
- `PLANNING` 期间再改，顺延到下一波（该波已在进入 `PLANNING` 时锁定）。
- 两次 `PLANNING` 之间多次编辑，以最后一次为准，版本历史保留。
- **Prompt 长度上限为 5000 字符**（2026-09-22 确认，服务端 `MAX_STRATEGY_LENGTH`；此前为 2000，因真实策略经常超限而提升）。超限时服务端返回 `STRATEGY_TOO_LONG`，该波 AI 不行动（fail closed）。
- 改动不消耗资源，也不重新开始游戏——波次、金币、基地生命、炮台、敌人与地图状态全部保留。

为此存在四种对玩家可见的状态：

| 状态 | 含义 | 如何离开 |
|---|---|---|
| `IDLE` | **未开始**：模拟冻结，等待玩家写开场 Prompt | 玩家点击 Start |
| `RUNNING` | 本波进行中（正常 / 加速） | 到波次边界进入 `PLANNING`；或玩家 PAUSE |
| `PAUSED` | 玩家主动冻结，用于读战场与写 Prompt | **只由玩家手动 RESUME**，绝不自动恢复 |
| `PLANNING` | 每个波次开始前（含第 1 波）的 AI 思考时间 | AI 思考完成后自动开启该波 |

波的推进由 `PLANNING` 完成驱动，不再由固定计时器（原 `delayBetweenWaves`）驱动。`PLANNING` 在**每个波次开始前**触发——第 1 波也不例外，因此 AI 从第一波起就按 Prompt 布防；它与上一波之间不等待场上清空（残敌随暂停冻结）。AI 思考完成后**自动**开启该波，玩家无需介入。`PAUSED` 不是编辑的前置条件。是否在未来引入冷却、次数或资源成本尚未确定。

## 8. 硬币（Coin）—— 不在 Hackathon MVP 内

旧设计使用 **投入 1 枚硬币（INSERT 1 COIN）** 这一隐喻：一枚硬币代表无限塔防中的一次尝试 / 一条命，花费一枚硬币开始一局，失败后开始下一局需要另一枚。

**Hackathon MVP 明确不要求 Coin 经济**：进入游戏需要确认昵称与头像，编辑 Prompt 免费，重开一局免费。Coin 是否在未来版本作为实验预算回归，以及初始配额、补充与变现机制，均尚未决定。

## 9. 得分与排行榜

主要得分是**到达的波次（Wave Reached）**。

网页游戏有一个共享排行榜，方便黑客松参与者比较各自的成绩。MVP 的排行榜至少展示 **昵称 / 到达波次 / 本局成绩**，按到达波次排名。

排行榜基于每局表现，同时承认 roguelike 随机性意味着单次最佳成绩并不是对 Prompt 质量的科学测量。

点击排行榜用户查看其最高波次对局的策略 / Prompt 历史，是本次 MVP 的学习闭环；分叉（Fork）他人的 Prompt 仍属于未来范围。

### 已决定的排行榜规则（2026-09-22 起）

- **排名依据**：每个 UID 取其**最佳波次**（该 UID 所有对局中到达的最高波次），按降序排名。MVP 不引入其他评分模式。
- **平局规则**：波次相同时，**更早达成**该波次的记录靠前（时间以服务端记录的到达时间为准）。
- **反作弊 / 对局校验**：成绩**不得仅凭客户端上报入库**（`AGENTS.md`「不可信输入」）。采用服务端可校验的对局证据：
  - 客户端开始一局时，服务端签发一个对局会话（run id）；
  - 每到达一个新波次，客户端向服务端 append 一条该波次的记录；
  - 服务端**只信任自己记录的波次**：对局成绩 = 服务端记录的最大波次，客户端上报的「最终分数」不作为真值；
  - 服务端拒绝非递增波次与超出会话有效期的提交，并对读接口与写接口分别限流。
- **最佳对局 Prompt 链**：每个 UID 的排行榜行展示其最高波次对局中真正生效过的 Prompt 版本，按生效顺序排列；波次相同取更早达成者的对局。每局从该局开场 Prompt 开始记录独立链；低分局保留自己的链但不替换当前最佳链，只有打破该 UID 纪录后，公开展示的最佳链才切换到新纪录局。Prompt 文本对排行榜访问者公开，仅允许纯文本展示。
- **身份与资料生命周期（2026-09-23 确认）**：页面每次刷新后都要求重新输入昵称并选择头像。每次确认资料时服务端新建递增 UID；UID 是账号、对局、成绩和 Prompt 历史的关联主键，只在服务端与客户端内部使用，不显示在产品 UI。昵称和头像是该 UID 的展示资料，不参与身份校验或成绩合并。因此相同昵称和头像，只要 UID 不同，就是不同用户。系统没有密码、登录凭证或账号找回；服务端不会删除此前的用户、run、波次记录、Prompt 链或排行榜成绩。
- **旧数据迁移**：迁移前的 run 没有 UID，升级时将历史昵称按大小写不敏感分组补齐一个 legacy UID，并保留旧成绩与 Prompt 链。旧系统已把同名玩家合并，因此升级无法还原并拆分这些历史身份；新建的页面会话 UID 不会发生此聚合。
- **历史 ID**：`run id` 只是历史对局标识，不是用户身份。刷新不会恢复昵称、token 或当前 run；服务端不删除旧 run、波次事件或 Prompt 节点，也不重编号。
- **校验边界**：服务端校验签名 token、run 所属 UID、波次单调性与有效期，并以服务端已记录的波次计算成绩；波次仍由浏览器上报，服务端不重演游戏，因此这不是服务器权威模拟或反作弊证明。
- **离线边界**：排行榜读取失败时可以退化为本地展示；Prompt / 波次同步队列只存在内存中，刷新或页面关闭可能丢失尚未同步的事件，不会用本地草稿冒充公开历史。
- **模式排行榜与三榜聚合（2026-09-23 确认）**：
  - **AI 榜**：按每个 UID 的 AI 对局最高波次降序排列；
  - **人类榜**：按每个 UID 的人类对局最高波次降序排列；
  - **总榜**：合并每个 UID 在 AI 与人类两模式下的各自最佳记录，按波次降序、首次到达时间升序排列截取前十。同一 UID 若在两模式均有成绩，可在总榜作为两条带不同模式标识（AI / 人类）的记录独立展示。
  - **模式绑定与固定**：开局时通过 `POST /api/runs` 提交并锁定模式（`ai` 或 `human`）；后续波次事件严格绑定该 run 的模式，不能更改。旧 run 与旧本地记录缺省时视为 AI 模式。
  - **榜单切换循环**：榜单切换按钮从当前游玩模式对应的榜单开始循环：AI 模式为 `AI 榜 → 人类榜 → 总榜 → AI 榜`；人类模式为 `人类榜 → AI 榜 → 总榜 → 人类榜`。
  - **Prompt 历史权限**：AI 记录行保留 Prompt 历史查看按钮；人类记录行不展示 Prompt 历史按钮（人类挑战无 Prompt）。
- 随机性如何呈现、是否展示平均 / 中位数表现、回放，MVP 均不提供，仍未决定是否在未来引入。

### 共享排行榜实现（2026-09-22 起）

线上新增**服务端排行榜 API**，替换此前的纯前端本地实现，使不同设备、不同浏览器的参与者看到同一个排行榜。这正是「创建了用户以后其他人无法看到」这一现象的根因修复：此前记录只写在每个浏览器各自的 `localStorage` 里，天然不可跨设备共享。技术选型与隔离要求见 §14。

前端在 API 不可用时退化为**本地展示**（仅本机可见，界面明确标注非共享）；此时本地数据**不再作为任何共享排名或持久化的真值来源**。

Prompt 历史与排行榜共用同一服务端 SQLite：每局的生效 Prompt 以 `prev_id` 链接成单链表，run 保存链头；开场 Prompt 在 Start 时显式写入，因为它在 `IDLE` 已激活，不会触发后续的 `PLANNING` 版本变更监听。之后只记录实际生效的版本，未生效的临时编辑不会出现在历史中。公开读取接口按 UID 当前最佳波次对局返回完整链；新对局写自己的链，不覆盖旧对局链，纪录变化后展示的新链才随最佳 run 查询结果切换。

### 音频资源（2026-09-23）

页面使用独立的 `AudioManager` 管理背景音乐、进入新波次和结算音效。确认昵称后及战斗启动前保持静音；只有真正开始对局时才启动背景音乐并优先播放第 1 波专用曲，待机时操作静音开关也不能提前播放。2026-09-23 Demo 曲目决定：开局第 1 波播放 `inner universe（启动战斗专用不循环）.mp4`，第 151 波播放 `Freak Out (151波次专用曲).mp4`，第 201 波播放 `M01 謡I-Making of Cyborg （201波次启动此曲专用）.mp4`，第 256 波播放 `MVlithium flower(256彩蛋专用）.mp4`；四首各播一次，不参与普通循环，结束后返回普通曲目。其余 12 首 Demo MP4 与原有已授权的 `public/audio/background/background.mp3` 构成可替换的普通曲目池，每首结束后再选下一首，多首时不连续重复同一首。Vite 在开发启动和构建时收集 `public/audio/` 下的 MP4 和 `background/` 下的 MP3、OGG、WAV、M4A，音量为 0.24；四个数字 MP3 占位副本已移除。`wave.wav` 与 `game-over.wav` 仍是短小、低音量、可播放的本地 PCM WAV 占位资源，旧的 `background.wav` 仅保留为历史占位文件，不再加载。音频不参与确定性模拟，自动播放被浏览器拒绝、资源缺失或解码失败都不会阻塞游戏；页面提供统一的静音开关。

Issue #71 的音频状态决定：普通曲目不再从全部 13 首中跨阶段混选，而是按 `audio-playlist.json` 的 Demo 配置分别归入战术/调查（1–150）、九课受围（151–200）、最后防线（201+）三个阶段；四首节点专用曲仍按上述约定各播一次，结束后进入当前阶段的普通曲池，具体配曲可经配置替换，无须改音频逻辑。第 151/201/256 波在该波实际开始时淡出旧曲再淡入专用曲；第 200 波到达时做短暂降音供“DISTRIBUTION: 100% / MISSION ACCOMPLISHED”呈现，第 201 波转场淡出后再留 600ms 静音节拍；不新增文字事件，也不暂停游戏模拟。AI 开战按钮/人类确认昵称属于用户手势；自动播放拒绝后只在下一次用户交互时尝试恢复。暂停、隐藏标签页、静音均暂停声音，恢复时只保留一个播放实例；音效和音乐共用静音与内部音量比例。换模式整页重载；音频层也支持重开时重置阶段与结束状态，不引入同页引擎重开功能。此前的全库轮播规则被本阶段分池规则取代，理由是需要让音频在节点曲结束后仍维持阶段叙事。

上述 16 首 MP4 的再分发授权**尚未确认**；按本次明确决定只为临时 Demo 接入播放，不意味着已获授权，也不改变「新增音频时确认资源许可归属」的正式发布要求。资源目前仍由 `public/audio/` 进入构建产物；非 Demo 发布前必须取得许可或替换/移除，不提供自动下架保证。

> **阶段纪律破例（2026-09-22）**：`AGENTS.md` 的阶段门槛要求「#6（P0 验证）通过之前，不要新增底座以外的系统」，而共享排行榜后端正属于底座以外的系统。本次经明确确认**破例**推进，理由是 §13「当前 MVP 边界」已把「面向参与者的共享排行榜」列为 MVP 必须项，且现场多人体验依赖它。破例仅覆盖排行榜后端；多 Agent / Swarm、Prompt 卡牌、Prompt 对抗等其余未来范围的禁令不变。

### 开发模式（人工 QA，2026-09-23 确认）

线上提供**开发模式**入口，供人工 QA 快速跳到指定波次（含特殊音乐波次 151 / 201 / 256）验证正常执行，而不必逐波打到那里。这是**人工 QA 工具，不是 AI 能力**：LLM 不参与、不可调用，扳手入口只在人类点击后出现。

- 入口在右上角扳手图标，点头像确认创建页面会话 UID 后可用。输入开发密码后，服务端把该 UID 标记为**不计榜**（`dev_sessions` 表）。密码无尝试次数限制；服务端未配置密码时入口 fail closed（返回 `DEV_MODE_UNAVAILABLE`）。密码只存在于服务端（`PD_DEV_PASSWORD` 环境变量或 `PD_DEV_PASSWORD_FILE` 文件），绝不进前端源码、构建产物或提交；服务端用 SHA-256 摘要 + `timingSafeEqual` 常量时间比较。
- 解锁后、开局前可设置**起始波次**（1–9999 整数）与**起始战术资源**（0–1,000,000,000 整数），引擎侧再校验范围与整数性。游戏开始后参数锁定，拒绝修改。
- 开发对局**绝不进入共享排行榜、本地排行榜或 Prompt 链**：客户端跳过 `RunSync` 与 `submitRunScore`；服务端 `POST /api/runs` 对 `dev_sessions` 的 UID 返回 `403 DEV_SESSION_UNRANKED` 作为最终保险。即便客户端伪造，也无法产生计榜对局。
- **仅 AI 指挥模式支持开发参数**。人类模式在昵称确认后立即自动开始计榜对局（防止在开发解锁前意外创建排位运行），无法在开局前安全设置自定义起始波次；`DevPanel` 在人类模式下明确说明此限制，而不是静默跳过。
- 状态机：`locked → unlocked`（解锁后幂等），`IDLE` 时可改参数，`RUNNING` 后锁定。`enableDevSession` 只在 UID 尚无任何 run 时生效（已有计榜对局的 UID 不能再切开发模式，返回 `409 RUN_ALREADY_STARTED`）。页面刷新按 §14 创建新 UID，原开发会话随旧 UID 失效。

## 10. 网页 / 现场体验

产品是一款**网页游戏**。

黑客松版本应允许现场的人直接用自己的浏览器参与，而不需要安装。

期望的现场循环是：

打开游戏 → 输入昵称并选头像 → 理解“我教 AI” → 选择或编写策略 → AI 作战 → 需要时暂停并更新策略 → 本局结束 → 出现得分 → 排行榜 → 再试一次。

共享的实时排行榜是产品概念的一部分。

**中央地图视口（2026-09-23 确认；最小缩放语义 2026-09-24 修订）**：地图显示在固定居中的窗口中，窗口位置不随相机缩放改变。最小缩放按地图与窗口尺寸取较大的比例（cover 语义）：缩到最小时地图任何一维都不得小于窗口，至少一维恰好顶住窗口边框，另一维与放大时一样越出窗口；相机中心同步钳制，保证窗口内任何时候（含拖拽、键盘平移）都不露出地图以外的背景。最大缩放不设上限。双击地图进入沉浸模式时，控制 UI 与地图窗口装饰框同时隐藏，地图可视区域尺寸保持不变。

**小地图**：显示全图障碍物、基地和当前视口，可点击或拖动来移动视口。控制面板展开时，小地图放在桌面作战扇区内，避开扇区外的不透明遮罩；窄屏控制卡片遮满作战扇区时暂不显示，也不拦截卡片点击。收起控制面板后，小地图显示在画布右下角。

**刷新加载态（2026-09-23 确认）**：页面首次打开或刷新时先显示与战术终端一致的深色加载态，隐藏未初始化的战场 HTML；等主样式及昵称门禁就绪才展示游戏，不增加人为等待。首屏样式不依赖 JS 或外部字体，长时间未进入时提供重试入口；动效遵循系统减少动态效果设置。

## 11. 核心产品神奇时刻

本项目的核心证明是：

**玩家改变 Prompt，AI 改变行为，战场作为结果发生可见变化。**

这应该在不同局之间，以及同一局内策略更新之后，都可以被观察到。

如果 Prompt 的改变不能产生清晰可辨的行为差异，核心产品就不成立。

## 12. 产品定位

当前简洁表述：

**Prompt 是你的策略。AI 是你的玩家。塔防是这个世界。**

面向玩家的表述：

**教你的 AI。把它送上战场。看它能活多久。**

更深层的教育命题是：玩家通过观察指令如何变成行动，并基于真实结果修订它们，学会如何向一个自主 AI 传达意图。

## 13. 当前 MVP 边界

MVP 必须建立：

- 一款网页版塔防游戏；
- 无限波次；
- roguelike / 随机化遭遇；
- 一个能自主操作游戏的 AI；
- 昵称与头像输入、按页面会话创建 UID（无可恢复账号体系）；
- Quick Start 策略与玩家可编辑的策略 Prompt；
- 一局进行中的 PAUSE / 修改 Prompt / RESUME；
- 正常速度 / x2 / x4 / x8 循环切换；
- 可见的 AI 行动与战场结果；
- 以“到达的波次”为主要得分；
- Game Over 与 Wave Reached 记录；
- 结算画面（波次 / 名次 / 本局统计）；一局在窗口失去焦点后仍继续运行至基地被摧毁；
- 波次固定路线自动推进（1–4 路，第 1/51/101/151 波边界切换）与天然机油道具；
- 界面语言可中 / 英切换（默认中文，选择持久化在 localStorage）；
- 面向参与者的分模式与总排行榜（AI / 人类 / 总榜，支持模式标识与 AI 提示词历史）。

第一个工程里程碑是把选定的开源网页塔防基础改造为可被 AI 操作的无限模式，见第 14 节与 issue #7。

### LLM 供应商

采用 **DeepSeek**。

这不是一次自由选择，而是由部署环境的网络约束决定的。在目标服务器上实测（2026-09-21）：

| 端点 | 结果 |
|---|---|
| `api.anthropic.com` | HTTP 403 `Request not allowed` —— Cloudflare 地域封锁 |
| `api.openai.com` | 完全不通，DNS 被污染至哨兵地址 |
| `api.deepseek.com` | HTTP 401 `Authentication Fails` —— 仅缺密钥，链路正常 |

DeepSeek 走国内 CDN 线路，实测 TLS 握手 25–80ms、请求总计约 100–160ms。由于 `docs/IDEA.md` 把决策延迟设计成了游戏机制（「Think fast or die」），低延迟链路对玩法本身有价值，而不只是运维收益。

同一约束也意味着：**玩家浏览器在国内网络下同样无法直连 Anthropic / OpenAI**，因此 LLM 调用必须经由服务端代理。这与密钥不得进入前端的要求方向一致。

### 部署环境约束

部署目标已确定，是一台位于中国大陆、已承载其他生产业务的小规格共享服务器。具体主机、凭据与运维细节由运维负责，不在本仓库记录。

对开发有约束力的是以下三条，与具体主机无关：

- **构建不在服务器上执行。** 目标机内存余量有限，构建峰值会挤压既有生产服务。前端构建在本地或 CI 完成，仅上传产物。
- **新服务必须与既有生产业务隔离**：独立系统用户、独立数据库、进程内存上限、反向代理限流。
- **LLM 调用必须经服务端代理**，原因见上一节。

资源规格本身不是瓶颈：游戏的 LLM 调用是 I/O 等待而非 CPU 密集，真正的上限来自模型供应商的速率限制与成本，而不是这台机器。

### 前端部署流水线

静态前端的持续部署已建立（2026-09-22 确认）。

- **触发与构建**：push 到 `main` 由 GitHub Actions 构建，PR 只构建不部署。构建在 CI 完成，
  仅把产物上传到服务器，符合上一节「构建不在服务器上执行」。

### 后端服务与数据库（2026-09-22 已选型）

排行榜需要**服务端共享存储**——这是「不同设备看到同一个排行榜」的前提。选型如下：

- **后端技术栈：Node.js 22 内置模块**（`node:http` 提供 HTTP、`node:sqlite` 提供数据库、`node:crypto` 提供会话签名），**零运行时 npm 依赖**。依据：目标机已装 Node 22（≥22.13，`node:sqlite` 免 `--experimental-sqlite` flag）；服务器上不需要 Python，也不需要安装任何包管理器依赖；与前端共用同一条 TypeScript 工具链，编译在 CI 完成。Express / Fastify / better-sqlite3 等框架级依赖**刻意不使用**——`node:http` 与 `node:sqlite` 对这点 API 面已足够，多一个依赖就多一份服务器侧风险（`better-sqlite3` 之类的原生编译正是旧 `engines: >=14 <18` 约束的来源）。
- **数据库：SQLite（WAL 模式），独立数据库文件。** 依据：黑客松规模数据量小、写入者少；零运维、单文件、易隔离、易备份。不引入 PostgreSQL / MySQL 的运维负担。
- **身份：服务端递增 UID + 页面内存中的签名会话 token，无账号登录体系。** 每次确认昵称与头像即创建新 UID；刷新后重新确认会创建另一个 UID。昵称和头像只作展示资料，UID 不显示在产品 UI。输入沿用 `sanitizeUsername` 校验与渲染转义规则（`AGENTS.md`「不可信输入」）。
- **成绩校验**：见 §9「反作弊 / 对局校验」。

§14 上文的四条隔离要求按如下落地：**独立系统用户**（不复用静态站的 `deploy-prompt-defense` 账号）、**独立 SQLite 文件**、systemd `MemoryMax=` 进程内存上限、nginx `limit_req` 反向代理限流。unit、端口、路径与部署流程见 `deploy/README.md`。

**「不在服务器上构建」仍然成立**（§14 硬约束）：后端 TypeScript 在 CI 编译成 JavaScript，服务器只接收编译产物并运行，既不执行构建、也不安装依赖。

**后端随前端版本一起版本化**：编译产物落在 `releases/<sha>/server/`，`current-server` 符号链接原子切换，回滚方式与静态产物一致。服务重启不依赖部署用户的任何特权——systemd unit 用 `Restart=always`，进程检测到版本变化后自行退出、由 systemd 拉起（见 `deploy/README.md`）。

排行榜后端服务已经部署；同一 Node 服务现也提供 `POST /api/agent/decide` 作为 LLM 代理（issue #22）。会话 token 用于准入，服务端持有模型密钥、系统指令和工具 schema；浏览器只提交玩家策略与战场快照，动作仍由游戏引擎验证。`GET /api/health` 的 `providerConfigured` 可供运维确认代理是否拿到密钥。

**后端环境配置的唯一真值来源是 `/etc/pd/pd-leaderboard.env`（issue #135，2026-09-24 确认）**：systemd unit 不再内联 `Environment=`，只用 `EnvironmentFile=` 指向它。`bootstrap-server.sh` 对 env 文件做幂等合并——必需键缺失才补、provider 键传参才写不传则保留、非托管键（如 `PD_DEV_PASSWORD_FILE`）永不触碰——因此重跑 bootstrap 不再静默抹掉运维手加的配置。env 文件只放路径与端点/模型名，不放密钥本身（密钥仍在 `data/` 下 600 文件里）。具体合并逻辑、自检与取舍见 `deploy/README.md` §5、`deploy/render-unit.sh` 与 `tests/render-unit.test.js`。
